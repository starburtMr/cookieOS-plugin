# 共享开发经验

通用接入规则见 [开发约定](development.md)，市场规则见 [市场维护](market.md)。本页只沉淀经过验证、能被后续插件复用的结论，不重复复制协议文档。

## 记录方法

每条经验记录日期、适用插件或版本、问题现象、原因、处理方法、验证依据及失效条件。详细证据放在相关插件目录，本页链接到来源。未经验证的判断标注为待验证，不作为强制规则。

插件专属业务留在插件目录。SDK 或宿主升级时复核受影响结论；过期结论标注失效原因并链接替代方法。记录不得包含凭据、用户数据或开发机私有路径。

## 当前状态

已有 Ctool 0.1.0 的本地开发与候选打包案例；真实 cookieOS 安装、模型/MCP 和生命周期验收仍待独立实例，不能以模拟替代。


## Ctool 本地迁移（2026-10-30）

适用：SDK 1.1.0、Vue 3、Pinia 持久化插件 4.x、Node >=22。依据：[Ctool 进度与验证](../ctool/Progress.md)、[实际设计](../ctool/High-Level-Design.md)、[检查入口](../ctool/package.json)。

| 现象与原因 | 已验证处理 | 复核条件 |
|---|---|---|
| 原页面弹层失效：ES module 入口没有原 HTML 中的 Teleport 目标 | 挂载前补齐自己的弹层节点；逐项打开真实对话框验证，路由冒烟不能代替弹层交互 | 页面壳、入口或弹层组件变化 |
| 同步 Pinia storage 无法直接返回 xhub Promise；读失败后可能误写默认值 | 启动先读取允许的偏好，保留同步内存镜像；逐键串行写入并保留失败反馈。部分读失败不自动覆盖远端 | 持久化插件/桥语义变化；增加敏感历史前重新核定隔离 |
| SDK pack 递归收集目录，宿主不执行 npm 安装钩子 | 只组装干净目录，Node 依赖随 bundle 提供；在没有开发 node_modules 的临时目录启动服务，再检查和打包 | SDK pack 排除规则、运行时或依赖变更 |
| 单次 Worker 模块记录会遗漏其他 Worker 的依赖与许可 | 合并全部 Worker 和主界面的构建输入，按实际版本核对审计及许可；不把全工作区告警与实际包混同 | Worker 拆分、构建器或依赖变更 |
| 只有空文本框的页面被 toBeEmpty 误判为未挂载 | 检查实际控件节点和可见操作，再分别断言业务结果；保留失败证据并区分测试错误与产品缺陷 | 测试定位或渲染结构变化 |

更多 Ctool 业务差异留在插件目录。上述结论仅覆盖已记录的本地检查，不声明真实宿主 CSP、外部服务或全部浏览器兼容性。
