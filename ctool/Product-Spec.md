# Ctool 开发者工具箱

状态：需求已进入执行方案编制，尚未开始插件实现。联网功能全部保留已确认；已重新下载并核实公网 SDK 1.1.0 的宿主模型接口。技术设计见 [High-Level-Design.md](High-Level-Design.md)，阶段依赖见 [DEV-PLAN.md](DEV-PLAN.md)，具体模块任务见 [doc/tasks/cookieos-migration](doc/tasks/cookieos-migration/README.md)，实际记录见 [Progress.md](Progress.md)。

## 1. 产品定位与本轮目标

将用户提供的 Ctool 工具箱迁入 cookieOS，让开发者在同一个入口完成数据处理、编码转换、加解密、代码处理、网络调试和 AI 辅助。

复用已有工具实现及交互，不重新编写一套缩水工具箱。首版以附件中登记的 60 项工具、88 个功能入口为迁移基线；这两个数字表示配置登记数，不代表所有算法、子页面和按钮的数量，也不代表已经实现或通过验收。

本轮先梳理需求。最终开发交付应包含源码、独立可安装 ZIP、SHA-256、使用说明、检查记录及真实宿主未验证项。需求文档本身不代表插件开发完成。

### 已确认

- 安装目标为 cookieOS 扩展，不是浏览器扩展或独立桌面程序。
- 每个插件位于仓库根目录的独立业务文件夹；本插件使用 `ctool/`。
- 保留全部联网功能；需要凭据的功能在配置后启用，外部服务失败有明确反馈。
- 新版 SDK 支持调用 cookieOS 已配置模型，模型接入沿用宿主能力，不要求重复配置模型供应商及密钥。
- 本地开发规则、技能、工具配置、私钥、运行数据和真实凭据不进入公开源码或安装包。
- 没有独立测试环境和相应授权时，不安装到正在使用的 cookieOS 服务器。

### 当前建议，区别于用户已确认内容

- 保留原有 12 项 AI 辅助，将模型调用切换为宿主模型。
- 初版按14个结构化工具交付；2026-10-31用户已要求完整业务能力开放，当前范围以“完整AI/MCP工具化”条目与覆盖矩阵为准。
- 默认以完整页面使用工具箱，并提供浏览器页面内浮窗；是否同时开放 module、drawer 由实际适配结果决定，不因模板列出便承诺全部可用。
- 复用原有分类、搜索、常用工具、历史、中文与英文、主题及缩放能力；适配宿主主题，不另立一套品牌设计。
- 保留工具范围，移除原第三方使用统计及与迁移无关的更新推广行为。业务联网不通过原公共代理转发。

### 通用使用体验

- 用户通过分类、名称和已有关键词搜索工具，选择后进入对应操作页面；无匹配时可清空或修改搜索。
- 保留原本适用的粘贴、导入、转换、复制、导出和结果展示。文件由用户主动选择，不能将浏览器文件选择误当成服务器文件路径。
- 复制被拒绝时提示手动复制，不显示虚假的“复制成功”；默认不自动读取剪贴板。
- 切换工具与形态时不静默覆盖当前输入；草稿与历史按明确的数据规则处理。
- 输入错误时保留原内容并指出可修正的问题；无效结果不作为成功结果替换现有内容。
- 工具可在窄窗口下操作；长文本、表格、代码和编辑器有可控滚动，不撑破宿主布局。
- UI 文案简洁，表达结果、影响和下一步；不添加解释内部实现或技术保证的提示、Tooltip 或折叠说明。

## 4. AI 能力

### 4.1 原有 AI 辅助：插件调用宿主模型

迁移基线为原包登记的 12 项辅助：JSON、正则、Cron、SQL 参数填充、堆栈分析、配置转换、HTTP 代码片段、代码处理、文本处理、差异比较、URL 解析、User-Agent 解析。

建议行为：用户主动输入要求，结合当前工具内容生成建议或解释。保留原功能意图，不把普通格式化、编码或校验强制变成模型请求。

- 默认跟随 cookieOS 默认模型；允许选择宿主已配置模型，保存稳定模型引用，不保存数组位置或仅保存显示名称。
- 选择只影响本插件，不修改宿主默认模型；指定模型删除或停用时提示重新选择，不偷偷换模型。
- 不在插件内再维护模型供应商、Base URL 或模型 API Key 设置。
- 无可用模型时引导至宿主模型供应商设置；缺少新版能力时明确要求更新，普通非 AI 工具保持可用。
- 支持流式输出、停止、成功、失败、超时、输出截断和结果未知；失败与停止后保留已收到内容。
- AI 建议与已校验结果分开；替换现有输入须由用户明确触发。生成 SQL、代码、Shell 或正则不等于执行它们。
- 有格式约束的建议先做对应校验；格式错误明确反馈，不把“收到文字”当成正确结果。
- 不因断线自动重发模型请求；结果未知时按已有调用 ID 查询。停止不代表上游一定未执行或不会计费。
- 模型列表中的“配置完成”不能当成真实调用成功；真实验收需要一次受控生成。

### 4.2 宿主 AI / MCP 调用插件工具

这与上一节方向相反：宿主或外部客户端提交结构化参数，插件返回结构化结果。原有 AI 辅助不会自动变成工具暴露。

初版执行方案选定首批 14 个纯计算操作（历史交付范围，当前扩展目标见文末）：JSON 格式化/语法校验、Base64 编码/解码、URL 编码/解码、Hash、时间转换、进制转换、Cron 解析、文本处理、JSON/YAML/TOML 配置转换、URL 解析及 UUID 生成。各操作的合同与边界见技术设计；全部界面功能仍按 60 项 / 88 个登记入口迁移，不因首批工具数缩减界面范围。

- 同一能力的 UI、内置 AI、MCP 复用业务实现及工具定义，不维护三套计算逻辑。
- 后端重新验证参数及结果；HTTP 200 不代表工具业务成功。
- 只选择适合结构化结果的操作。图形编辑、选择本机文件、剪贴板等界面行为不凭空成为后台能力。
- 初版暂未开放的密钥业务、WebSocket消息和JDoodle代码运行现已纳入完整工具化目标，按真实输入/效果/费用和结果未知约定实现。任意服务器命令执行仍不属于Ctool现有业务。
- 调用宿主模型与暴露 AI / MCP 工具的开关各自遵循 SDK，不额外创造模型授权开关。

## 5. 联网功能：全部保留

| 功能 | 原版依赖 / 行为 | 迁移需要明确的结果 |
|---|---|---|
| IP 查询 | GeoJS；未指定 IP 时返回请求发起方的公网 IP | 保留查询；若请求经插件后端发出，“当前 IP”指服务器出口，不能标成访问者电脑的 IP |
| WebSocket | 浏览器直接建立 WebSocket 连接 | 保留连接、发送、接收、日志与断开；初版建议沿用浏览器连接语义，不能用服务器代理悄悄改变网络位置 |
| ARM 与机器码转换 | armconverter.com 的转换接口 | 明确为在线转换；失败时保留输入并给出下一步，不伪造本地转换成功 |
| 在线代码运行 | JDoodle 的 client ID / secret 与外部执行接口 | 配置后启用；代码在第三方服务运行，不能改成在 cookieOS 管理服务器执行任意用户代码 |

- 第三方凭据通过宿主秘密配置进入服务；不能保存在浏览器普通设置、工具历史、日志、源码或 ZIP。
- 不沿用 Ctool 原公共代理传送代码和凭据；后端只实现本插件明确需要的请求，不建立开放式任意 URL 代理。
- 对外提交代码、连接目标及发送内容须由用户主动触发，并在相关操作处表达实际外部影响和可能费用。
- WebSocket 的浏览器 HTTPS / WSS 约束、目标网络可达性及权限失败如实提示；服务器能够访问不代表浏览器能够访问。
- 缺少凭据、网络不可达、限流、认证失败、超时和外部响应无效分别给出可操作反馈；不显示含秘密的原始错误。
- 在线执行及消息发送可能已有外部影响；超时或断线不能自动重放。重试须由用户判断并主动触发。
- 停止等待、关闭窗口、停用插件、更新或回退代码不能承诺撤销已发送的消息或第三方已经开始的运行。

## 6. 数据与隐私补充

以下为建议默认行为，需在后续详细规格中落实到具体工具。

| 数据 | 保存与使用规则 |
|---|---|
| 常用工具、语言、主题、缩放、模型选择 | 使用插件自己的宿主存储；不改变其他插件或宿主默认设置 |
| 普通操作历史 | 提供明确开关与清空；关闭时不新增内容，清空时说明无法恢复；默认不持久化工具输入/结果 |
| 密码、私钥、加密密钥、签名密钥、JWT、令牌及含认证信息的请求 | 不进入普通历史或诊断日志；不能仅依赖字段名称过滤，涉及这些内容的工具默认不保存完整负载 |
| 文件和图片 | 用户主动导入与导出；独立说明超大内容限制，不自动访问服务器任意文件 |
| 模型输入 | 仅提交当前操作明确选择的内容；不自动携带宿主聊天历史、其他插件数据、凭据或全部工具历史 |
| 第三方统计 | 原包存在统计上报实现；迁移版移除该上报，不将其作为业务联网保留 |

浏览器内计算、cookieOS 服务端处理、第三方服务处理是不同的数据去向。不能笼统宣传“所有数据都只在本地”；详细设计应按功能列明实际路径。

历史若采用宿主 KV，需核对宿主用户隔离语义；在未核实前，不承诺同一实例多用户之间的数据私有性。敏感工具的浏览器本地计算优先保留，确需后台调用时明确相应数据会提交到服务器。

## 7. 交付与验收标准

### 基础交付

- 源码目录为 `ctool/`；独立插件身份建议 `io.cookieos.ctool`、显示名 `Ctool 开发者工具箱`、首个插件版本 `0.1.0`，安装前核实身份可用。插件版本与上游 2.9.1 分开记录。
- 采用满足已选能力的运行形态：保留后端工具与第三方凭据时优先 Node；模型调用本身不强制需要 Node。开发环境 Node 与宿主运行要求分开验证，不依赖安装时执行 npm/pip 钩子。
- 按实际能力声明 manifest、桥能力、外链权限、工具参数/结果合同及运行入口；不保留示例身份或 echo/sum 演示工具作为产品功能。
- 使用经过核定的 SDK 完成 check 与 pack，ZIP 放在插件目录外，已有输出不覆盖。
- ZIP 根目录含 manifest 和声明入口、全部运行依赖及所需许可证；无额外项目外壳，无开发框架、凭据、运行数据或无关平台产物。
- 提供 ZIP 的绝对路径、文件大小、SHA-256、运行环境、配置步骤和逐项检查记录。

### 功能验收

- 建立 60 项 / 88 登记入口的迁移对照，每项注明保留、替代或经用户确认排除的行为；全部保留的联网能力不能仅留下禁用按钮便算完成。
- 各类工具有代表性成功与失败样例，并覆盖加解密、编码与大整数、时间及时区、正则和格式转换等适用边界；超长输入和高成本运算有明确限制，不能卡死界面或服务。
- 12 项原 AI 辅助分别核对输入、输出用途、替换动作与失败反馈，不以一次通用聊天成功代替全部迁移。
- 模型验证覆盖默认/指定选择、无模型、失效选择、流式完成、停止、超时、断流、部分文本与结果未知。
- 实际暴露的每个 AI / MCP 工具均验证 Schema、服务端校验、业务成功/失败及 UI 一致性；未暴露的功能不宣传为 AI / MCP 能力。
- 联网功能核对请求来源、缺配置、连接/断开、服务错误、超时及已发送结果未知；无凭据时只报告“未验证真实外部执行”。
- 验证声明的界面形态、主题、窄窗口、复制/导入/导出和可访问性基本操作；模型生成内容和外部响应不得作为不可信 HTML 执行。

### 宿主验收与安装说明

在独立且获授权的测试实例中，分别验证安装、真实 UI、宿主模型生成、内置 AI 工具、真实 MCP 客户端调用、停用与更新。SDK check、模拟测试和打包均不能代替这些验收。

没有环境或凭据时交付 ZIP 和手动步骤，明确未验证项目。安装入口：<https://cookieos.yxysj66.com/extensions?tab=installed>，点击“安装扩展”并选择“本地 ZIP”。

需要 AI / MCP 工具时在插件设置启用对应工具开关；外部客户端还需在“MCP 服务”中选择插件工具、配置服务与访问令牌。令牌不进入插件包。插件自身调用宿主模型不要求重复配置模型供应商。

## 完整 AI/MCP 工具化（2026-10-31，当前目标）

用户要求在现有Ctool基础上提供完整功能给内置AI与外部MCP，本轮已获独立worktree实现、验证与合回授权；发布仍须另行授权。原“首批14个”不再是完整交付的范围上限，旧已完成记录作为历史保留。

- 范围覆盖全部60类/88入口的实际业务操作与选项，包括现有12类模型辅助，详见[覆盖矩阵](doc/tasks/full-ai-mcp/capability-matrix.md)。界面支持不等于外部接口已实现。
- 保留14个旧工具合同及用户现有配置/数据，补齐编码/文件、JSON/转换、密码学、文本/代码、时间/计算、图像、网络/在线运行与模型辅助；不复制三份业务实现。
- 文件/图片结果必须可取得实际内容，不能只返回成功文字；Node不能读取浏览器本机文件路径、剪贴板或相机。这些交互由调用方传入内容承接。
- 密钥通过宿主秘密配置引用，私钥生成/导出以明确的临时文件结果承接；不新增密钥平台。网络发送、在线运行、模型调用准确声明效果、费用与未知状态，不自动重放。
- 保留浏览器原网络位置；MCP的网络能力明确在管理服务器执行。SQL、Docker、权限等转换不变成执行数据库/命令/修改系统权限。
- 完成定义是每个业务操作都有合同与运行证据、原接口兼容、真实隔离宿主与MCP验收及升级/回退保留数据；不承诺零bug，不以工具总数或构建成功替代验收。
- 目标新版本0.3.0在实际实现后递增；运行Node最低版本依据新依赖实际engine与宿主测试确定。SDK与所有生产依赖只用已验证目标，不擅改宿主源码/全局配置。
