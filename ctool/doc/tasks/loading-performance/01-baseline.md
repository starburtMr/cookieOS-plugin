# PERF-01：可重复基线与预算冻结

状态来源：[Progress](../../../Progress.md)。依赖：无。契约：[DD-PERF-02](../../../Detailed-Design.md#dd-perf-02-测量合同)。

## 目标与修改范围

先使一个轻量工具从打开到正确结果可重复测量，再扩到重型工具与全部打开形态。
复用tests/host_acceptance.py、tests/host-browser.mjs、Playwright及现有构建；拟新增tests/performance.mjs，必要时扩展scripts/serve-test.mjs的独立性能模式，报告保存在忽略的.cache/performance，脱敏摘要归档到doc/verification/loading-performance。
不修改宿主、不改业务算法；不使用page.route/context.route或HAR回放采缓存基线。

## 实施步骤

1. 记录Git提交、锁文件/包SHA、SDK/宿主版本、浏览器版本、OS/CPU、viewport、CPU与网络条件、压缩/缓存响应头、具体工具与surface。重建0.3.0基线并保留旧ZIP；已有6.4MB快照只作核对线索。
2. 用生产产物和可控制的隔离宿主建立性能访问路径；实际SDK桥，不把立即返回的mock storage当宿主延迟。现有host-browser路由夹具仅复用交互定位，不复用其网络传输方式。
3. 默认入口与直达工具分别测；恢复上次入口分同实例和新实例。当前没有跨新实例持久恢复，验证真实选择结果即可，不扩功能或新增持久化。
4. 至少覆盖hash、Base64、代码编辑、JSON、数学计算、diff；每次用固定无敏感输入完成编辑/执行/结果断言。先检查实际控件和手动/自动执行方式，不以框架渲染或Monaco DOM出现作为结束。
5. 每个核心场景冷开5次、缓存新实例重开10次、同实例首次/重复重工具10次；连续切换30轮、关闭重开10轮。四种surface都做结果回归，完整性能组固定view，其他形态至少各3次冷/暖记录。
6. 冷缓存用独立浏览器上下文或隔离缓存重置；暖缓存同上下文同资源URL创建新插件实例。保留偏好与HTTP资源缓存的条件分开控制；iframe实例URL变化时原样记录，不能改宿主URL伪造命中。
7. 开始采集早于点击打开/iframe创建。记录t_open→可输入→正确结果，设置读取/脚本执行区间、请求发起链、资源时间/字节与长任务；资源同一请求去重，重定向和失败重试另计。脚本解析/执行需要trace证据，不能从下载时长推算。
8. 冻结baseline.json、测量脚本及DD-PERF预算公式对应的budget.json，随后才开始修改。before/after交错测量，不挑最快一次；median/min/max和全部样本保留，N<20不报告稳定P95。

## 必要验收

- 同场景重复测量可得到真实业务结果；cold确实未用缓存，warm缓存状态有浏览器/响应头证据，未命中要如实报告。
- 请求/代码体积与网络传输明确分列；TAO或API受限标unknown，不能用0代替未知。
- 自动复制关闭只用隔离测试设置；不保存用户正文、完整偏好、令牌、Cookie、请求头或生产trace。
- 没有隔离宿主时可先做标注为本地桥夹具的基线；宿主点击打开→结果不能关闭验收，相关比较暂不作发布依据。
- 保存基线的环境、命令、原始样本与预算，预算不依赖候选结果反向放宽。
