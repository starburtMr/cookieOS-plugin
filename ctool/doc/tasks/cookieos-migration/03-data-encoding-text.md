## C1：迁移数据与文本计算

**前置任务：B3、C3。**

**目标：** 保留原页面与所有登记入口，不将已有格式/编码算法重新实现。

**修改范围：** `packages/ctool-core/src/tools/` 中的 base64/base32/base58、URL/Unicode/HTML 等编码，JSON、MessagePack、序列化、配置、进制/ASCII/MongoID，文本/拼音/变量转换/差异/中文数字/代码格式化，以及 URL 解析、HTTP 片段、UA、Docker Compose 纯解析界面；相关 helper、组件与现有测试。

**执行步骤：**
1. 按矩阵逐项迁移；共享 Base64 使用 B3 入口，HTML/表达式/正则/压缩边界调用 C3。ARM 在线部分交 E2，code/run 交 E3，不因本任务完成就把它们记为通过。
2. 保留 Monaco、formatter、jsonrepair、JMESPath、MessagePack、原序列化与格式库；定向升级 JSONPath 候选并回归 safe 过滤、递归、null、无匹配、非法表达式。
3. 保留大整数精度和可观察的格式语义；不把 `null` 当错误，也不对其调用不受保护的 toString。格式无法表示时明确失败，不悄悄丢值。
4. UA 基础字段采用通过 A3 的 MIT 候选，验证原页面消费的 browser/engine/os/device/cpu；若字段兼容性不满足，先解决已有库选型，不能自行写识别数据库。
5. 修改 helper 时搜索所有直接/间接调用方、测试和动态路由；同一能力抽为 C4 共用前，先保留可验证行为。

**验收：** 每个负责入口有正确结果及非法输入样例；覆盖中文/emoji、无效 UTF-8、空/null、坏 URL 编码、2^53 之外整数、原型相关键、重复键策略和内容上限；配置转换不能出现“成功但丢值”。实际使用复制/文件导入导出，不能只有路由截图。

**证据：** 矩阵各项样例、对应原测试结果、定向依赖差异、库复用入口和引入回归；ARM/在线运行由各自任务补齐后才能完成整工具验收。
