# 真实宿主验收、回退与交付

输入：F3 的不可变候选 ZIP、[需求验收](../../../Product-Spec.md)、[技术设计](../../../High-Level-Design.md)。真实测试必须使用独立且获授权的 cookieOS 实例；不能擅自安装正在使用的宿主。状态见 [Progress](../../../Progress.md)。

<a id="g1"></a>
## G1：安装与真实界面

**前置任务：F3。**

**目标：** 证明最终 ZIP 在目标宿主能够安装、运行并加载实际资源。

**修改范围：** 隔离环境安装记录及针对发现问题的原模块修复；不改生产宿主或全局配置。

**执行步骤：** 记录宿主版本、Linux 架构和 Node 环境，核对 ZIP 摘要；通过扩展中心的“本地 ZIP”安装。验证身份/hostApi/平台/包大小限制和 models 实际能力，再测试 view/window、主题、窄窗、复制/导入/导出、所有登记入口和代表性运算。确认真实 CSP、安装资源路径、Worker/WASM 与服务身份握手。

**验收：** 无资源 404、占位界面或仅开发机可用的依赖；真实安装器接受，服务正常与业务错误分别可观察；浏览器数据/文件位置没有误当服务器路径。

**证据：** 实例与包版本、安装结果、真实页面及网络/服务观察。无实例或授权则本项待验收，不伪造、不阻塞其他已授权的独立本地工作。

<a id="g2"></a>
## G2：宿主模型、内置 AI 与真实 MCP

**前置任务：G1。**

**目标：** 分别验收三个不同方向的真实调用，不能相互替代。

**修改范围：** 测试实例模型/工具/MCP 配置与验收记录，访问凭据仅走安全测试配置。

**执行步骤：**
1. 插件调用宿主模型：受控生成测试默认/指定选择，逐项核对 12 项业务辅助的结果用途与采用动作，并测试缺模型/取消/超时/断流及迟到结果。
2. 宿主助手调用插件：开启对应工具开关，真实调用首批操作，核对业务结果与调用参数；列出模型或工具不算执行成功。
3. 在“MCP 服务”选择插件工具、配置访问令牌，用真实 MCP 客户端发现并调用，测试非法参数和开关关闭后的拒绝。令牌不进入源码、ZIP 或报告。
4. 使用授权 JDoodle 测试凭据做最小真实运行；缺凭据时保留该项未验证，不将 mock 返回写成真实成功。

**验收：** 模型、助手、MCP 和外部运行各有独立证据；AI/MCP 不能调用被排除的危险操作；开关变化、业务失败、未知结果不被当成成功，也不自动重发。

**证据：** 实际结果及经脱敏的调用标识、失败路径、开关行为。费用或凭据未授权时只暂停相关真实测试。

## G3：生命周期、回退与最终交付

**前置任务：F3。** 本地候选交付与工作区接回可独立进行；本任务的真实生命周期操作和完整验收结论另外要求 G1、G2 已通过。

**目标：** 验证停用/更新/回退不损坏自身数据，并交付源码和可追溯安装包。

**修改范围：** 测试用后续版本、隔离宿主生命周期记录、README、Progress 与本任务拥有的工作区接回。

**执行步骤：**
1. 生成测试后续版本而不覆盖已存在 ZIP；验证稳定 ID、偏好和版本数据处理，切回旧版本后旧配置不被新空值覆盖。
2. 关闭窗口、切工具、停用/启用、卸载均检查 worker/socket/流/监听器/timer 清理；更新/回退不能宣称撤销已发送的外部操作。
3. 修复验收发现的问题后重跑原失败、相关回归、统一入口及受影响真实路径，最终包重新记录摘要。
4. 依据基线三方接回主目录，只接回已验证的本任务变更，保护其他文件和索引；验证后清理自己的 worktree。提交/推送/Release/市场上架遵循各自授权，不自动推 main 或上线。
5. 提供源码与 ZIP 的绝对路径、大小/SHA-256、环境/配置/安装步骤、检查结果与未验证项。安装入口为扩展中心“安装扩展→本地 ZIP”，AI/MCP 工具开关与外部 MCP 服务配置分别说明。

**验收：** 真实验收齐全才能记录完整通过；如果无测试环境，只能交付本地已验证候选及人工步骤，G1/G2/G3 真实部分保持待验收，不能标记完整宿主验收或正式市场上架。

**证据：** 版本/包摘要、升级回退和清理记录、源码差异及最终交付清单。外部系统状态变化不会随代码回退撤销，仍需如实说明。

## 独立测试实例的手动验收顺序

1. 准备独立 cookieOS 测试实例（含 host-models 能力）与 Node.js >=22；先记录其版本与现有扩展/配置，避免生产实例。
2. 从 https://cookieos.yxysj66.com/extensions?tab=installed 的「安装扩展 → 本地 ZIP」上传交付 ZIP，确认 id `io.cookieos.ctool`、版本 0.1.0；记录完整安装器结果，不能以 dev.py check 代替。
3. 分别打开 module/view/window/drawer，验证 JSON、Base64、二维码、格式转换、剪贴板、主题、设置抽屉，缩放/语言/模型选择重新打开后仍正确。
4. 在宿主模型供应商中准备默认模型和指定模型；逐项点击 12 类辅助，检查流、采用、取消、换工具、修改输入、指定模型失效、断线与未知结果查询。记录真实模型与 callId，不记录密钥。
5. 开启插件的内置 AI/MCP 工具开关，检查 14 个纯计算工具的参数与业务失败；确认 ARM/JDoodle 不出现在 AI/MCP 清单。外部 MCP 在「MCP 服务」选择工具并配置服务/访问令牌后，从真实 MCP 客户端调用；不得将令牌放进包。
6. JDoodle 凭据仅填秘密配置；先查额度，再手动运行一段无写入代码。超时后先确认外部结果，不自动重试。ARM 和 GeoJS 记录当前网络可达性与浏览器 CORS；WebSocket 从浏览器执行，HTTPS 对 ws:// 的限制如实记录。
7. 保留旧包和配置备份，测试停用/启用、升级、失败升级与回退、卸载；检查旧流/连接/Worker 释放，确认已有外部操作不会因停用被误认为撤销。

以上需要独立实例及相应授权/凭据。本轮未执行，状态保持待真实验收。
