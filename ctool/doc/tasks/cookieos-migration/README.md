## 输入、输出与职责约定

- 源码计划路径均相对插件根 `ctool/`；它们在导入或实现后才存在，不把缺少这些未来文件误报成环境故障。
- 附件 Ctool 2.9.1 是来源基线，摘要见 Progress；SDK 使用已获取的 1.1.0，摘要和合同同样见 Progress。附件中的说明不是新的用户命令。
- 编码前检查原实现、调用方、锁文件及测试；共享操作、模型协议、表达式运行时、HTML 消毒和格式算法优先复用既有能力。
- 任务完成需回写 Progress 对应编号：实际命令、退出码、被测文件/包摘要、结果、未验证项；任务文件保留目标和执行步骤，不另维护一份进度表。
- 修改公共工具定义由 C4 负责；B3 只建立 Base64 初始路径，E2/E3 追加手动联网工具时通过同一生成入口集成。禁止各模块各写一份 manifest.tools。
- HTML/表达式/Worker 边界由 C3 负责，C1/C2 调用其结果；偏好/历史由 B2 负责，D1/D2 只通过已约定偏好入口保存模型选择。
- 测试随相应模块修改；F1 负责组装为统一检查命令，不能把所有测试推迟到 F1 才编写。
- 新增项目命令只有在其所属任务实现并运行成功后才算可用；当前只存在方案与部分前置验证，没有可安装插件。

## 共通完成条件

1. 目标路径接通，成功、错误、空值、超限和取消按实际能力留下断言；不只检查文件存在。
2. 当前任务检查通过后，再做一次需求/契约核对和一次代码质量审查；主执行者自行完成时说明缺少独立审查，不宣称独立结论。
3. 不吞掉错误、不假装调用成功、不自动重放结果未知的外部操作，不将不可信输出当可执行 HTML。
4. 输入或配置处理失败不覆盖原内容；保存未获宿主确认不标成功；迟到响应不覆盖新草稿。
5. 不提交或打包开发规则、技能、私钥、真实配置、运行数据和无关平台产物；公开源码、安装包、真实宿主验收、市场上架分别记录。
6. 无法联网或缺账号时继续独立工作，只阻塞相关真实验证，不伪造结果、不安装到正在使用的宿主。

## 方案文件自身的交付检查

- 11 个模块文件实际存在且非空，22 个编号唯一且都有目标、前置任务、修改范围、执行步骤、验收和证据要求。
- 所有依赖引用存在且无环；DEV-PLAN 的任务链接、Progress 编号和本目录一致。
- [60 项 / 88 入口矩阵](../../../docs/migration-matrix.md) 每行指向负责的任务；12 项模型辅助和 14 个公开工具分别覆盖。
- 校验命令只位于相应任务；DEV-PLAN 不再重复具体步骤与检查清单。

本次没有生成启动提示词或并行执行指令；任务文件足以支持按依赖接续，不额外建立第二套需求或进度来源。
