输入：[技术设计 §6](../../../High-Level-Design.md)、SDK models 类型、原 helper/llm 及调用方。B2 拥有偏好存储，C1/C2 负责业务结果校验。状态见 [Progress](../../../Progress.md)。

<a id="d1"></a>
## D1：替换独立模型接入

**前置任务：B2、C4。**

**目标：** 原有 AI 功能使用 cookieOS 已配置模型，复用 SDK 的请求、流和状态协议。

**修改范围：** `packages/ctool-core/src/helper/llm.ts`、原 `store/setting.ts` 中的独立模型设置字段/界面、相关类型和测试；存储入口调整与 B2 保持一致。

**执行步骤：**
1. 列出全部 chat/streamChat、AiConfig、独立模型字段和帮助文案引用，避免只替换 helper 而漏掉调用方。
2. 改用 `window.xhub.models.list/generate/stream/status/cancel`；复用 SDK，不再写 Base URL 拼接、供应商认证或 SSE 解析。
3. 默认选择跟随宿主，指定选择保存稳定 ref；失效时明确失败，不自动换模型或改变宿主默认。
4. 移除插件新增模型供应商/密钥配置路径；旧字段不迁入新偏好，不读取或展示旧明文值。第三方 JDoodle 凭据不受本项模型设置移除影响。
5. 缺 models 能力时指向更新，缺模型时指向宿主供应商设置；普通工具继续可用，不另加模型授权开关。

**验收：** mock 验证仅提交本操作消息、模型选择参数和 SDK 允许参数；配置/供应商异常可理解；未发起独立供应商网络请求，未把任何服务 token 放入 UI。SDK 客户端测试可以复用，但不代替插件适配测试。

**证据：** 调用方清单、旧设置引用清理结果、消息/模型选择断言及错误映射；不使用真实密钥或模拟真实模型成功。

<a id="d2"></a>
## D2：迁移业务辅助与生成状态

**前置任务：D1。**

**目标：** 完整保留 12 项原辅助意图，生成失败、停止和并发变化不损坏用户草稿。

**修改范围：** json、regex、crontab、sqlFillParameter、stacktrace、configConvert、httpSnippet、code、text、diffs、urlParse、userAgent 的原 AI 调用和交互、必要共享生成状态及测试。

**执行步骤：**
1. 逐项记录输入/提示词/结果用途与“采用结果”动作，复用原业务提示及校验库，不给普通确定性运算强加模型依赖。
2. 覆盖准备/排队/生成/完成/失败/取消/超时/未知/截断，保留部分文本、callId 和实际模型；用量缺失不估算费用。
3. 每次调用绑定页面、输入版本和当前调用 ID；修改输入、换工具、再次生成后，旧结果不得覆盖新内容。主动采用也要检查仍对应当前输入。
4. 流关闭/组件卸载释放读取器和订阅；不因断线自动重发。未知结果仅查询原 ID，宿主重启/过期后保持未知。

**验收：** 12 项分别有合适输入、可采用结果和非法建议样例；生成 SQL/代码不自动执行。对先 A 后 B 的乱序回复、生成中改输入、换工具、关闭窗口、所有流终态保留测试；模型失败不影响普通工具。

**证据：** 12 项业务样例和状态机断言；真实供应商调用只在 G2 的获授权测试环境记录，不把 mock 当真实验收。
