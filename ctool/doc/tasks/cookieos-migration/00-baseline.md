## A1：安全导入与来源保留

**前置任务：无。**

**目标：** 导入真实 Ctool 源码，不覆盖现有文档或无关改动，不把整个工作区当插件。

**修改范围：** `packages/`、原 `package.json`/锁文件/workspace 配置、必要构建配置、`LICENSE`、`README.md`；工作区隔离资料仅留本地忽略目录。

**执行步骤：**
1. 保存当前文档与工作区差异摘要；在独立 worktree 使用 `codex/ctool-extension`。已存在同名 worktree/分支时先核实归属，不直接删除重建。
2. 对附件核对已记录 SHA-256，在新临时目录检查 ZIP 路径、重复条目、链接及展开上限后解压；按允许清单导入，不能直接解压覆盖已有 `ctool/`。
3. 保留上游源码布局，记录 60 工具 / 88 登记入口及原 21 个 `.test.ts` 文件，测试文件数不当用例数。
4. 补入已核实的上游 MIT 正文及来源版本；内嵌代码/素材许可继续由 F2 核对。

**验收：** 附件与导入文件可按清单追溯；原业务源码未被提前改写；已有需求和设计文档不丢失；不存在穿越/链接/私密文件导入。

**证据：** 原始及导入摘要、导入允许集、工作区基线、测试文件列表；来源不明则只暂停相关导入。

## A2：固定工具链并运行原始检查

**前置任务：A1。**

**目标：** 区分原有失败与迁移引入失败，建立真实测试、检查和构建基线。

**修改范围：** 仅必要的包管理器固定和原检查运行环境；不先升级整个依赖树。

**执行步骤：** 导入后在插件根执行原有入口：

```sh
npx --yes pnpm@10.34.9 install --frozen-lockfile --ignore-scripts
npx --yes pnpm@10.34.9 run test
npx --yes pnpm@10.34.9 run check
npx --yes pnpm@10.34.9 run build
npx --yes pnpm@10.34.9 run lint
```

固定 Node 22；核对锁文件中的具体 GitHub 提交及实际依赖版本。若 esbuild 等缺少安装准备，只对原 allowlist 中经核实的构建依赖显式 rebuild，不能全量开放 hooks。原 `initialize` 会触及多平台构建时先检查脚本，不自动安装 Rust/Tauri 或执行发布。

**验收：** 每个入口都记录退出码和失败原因；缺依赖与测试断言失败分开；未修改原业务就得到基线。原失败需定位并纳入对应任务，不能靠删除测试或降低 lint 门槛消除。

**证据：** Node/pnpm/锁摘要、实际命令、失败测试清单和构建资源清单；完整审计在 F2，候选目录零告警不能代替它。

## A4：建立新增重复门禁

**前置任务：A2。**

**目标：** 复用已有本地检查能力，在业务修改前建立原始源码的存量基线。

**修改范围：** 项目可独立运行的 `check:duplicates` 配置及精确存量基线；本地开发框架留在忽略目录，不公开或打包。

**执行步骤：** 核对当前工具版本与 `--help`，扫描完整相关源码；只按来源排除依赖、生成和构建产物。对未修改的导入版本建基线，用临时明显重复样例证明新增重复会非零失败，然后还原该样例。具体参数依当前工具能力选择，不臆造选项。

**验收：** 原始基线通过，新增样例失败；命中新增代码时归并实际共享行为或记录精确例外，不为过检查重建基线。

**证据：** 固定版本、范围、基线摘要、正反例退出码。此命令由 F1 统一接入，不能在 hook 临时下载最新版。

<a id="a3"></a>
## A3：浏览器与候选方案前置验证

**前置任务：A2、A4。**

**目标：** 在大规模迁移前验证 Worker/WASM、原 lodash 预设、消毒策略和 UA 候选，避免仅靠 Node 样例选择方案。

**修改范围：** 可撤销的本地可行性样例、必要测试 fixture；正式功能实现分别交 B/C 任务，不提前搭第二套应用。

**执行步骤：**
1. 复用已通过的 SDK 8 项与候选 6 项证据，使用原 Vite 实际构建方式加载 QuickJS/Monaco Worker，断开 CDN 后验证本地资源。
2. 验证全部原 lodash 转换预设；禁用宿主绑定。增加大数组内建转换、递归、累积字符串分配、内存耗尽和 Worker 外部截止样例；不要运行无上限的压力输入。
3. 复查 [QuickJS #219](https://github.com/justjake/quickjs-emscripten/issues/219) 与 [#275](https://github.com/justjake/quickjs-emscripten/issues/275) 对所选发布包的影响。它们是上游问题报告，不能直接当成本项目已复现的漏洞；`setMemoryLimit` 存在也不等于已证明总内存受限。
4. 用 DOMPurify 固定白名单处理恶意表格，验证不执行、不外连及正常表格结果；不先用可建 shadow root 的 unsafe API 解析输入。
5. 用代表性桌面/移动 UA 比较 MIT 候选字段，记录差异；不是简单把版本号降下去。

**验收：** 实际浏览器资源加载和正常行为通过，危险输入可在预算内终止且不影响主页面；资源计量有明确边界。不能满足时暂停 C3 依赖路径，选已发布且验证过的修复版本/官方支持方案，不切回主页面 eval、不静默删除功能。尚未测试真实宿主 CSP 的部分在 G1 保持未验证。

**证据：** 浏览器/候选版本、构建资源、各样例结果和终止时间；确认受影响的路径及替代依据。库内部尚无证据的保证不能写进完成结论。
