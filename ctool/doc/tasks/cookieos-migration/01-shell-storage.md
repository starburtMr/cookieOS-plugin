## B1：建立唯一插件身份与模板接入

**前置任务：A1、A2、A4。**

**目标：** 创建业务插件入口，使用真实 SDK 合同，不覆盖已有目录。

**修改范围：** `manifest.json`、必要模板运行文件、插件 README 的身份/上游版本记录。

**执行步骤：** 用已核验 SDK 在新临时目录执行 `dev.py init ... --runtime node`，只接入必需文件。身份为 `io.cookieos.ctool`、显示名 Ctool 开发者工具箱、插件版 0.1.0，上游版单独记 2.9.1。默认 `view`，声明 `view/window`；删除示例工具身份。桥能力与 open-url 权限按实际调用分别声明，不为模型新增权限或开关。

**验收：** manifest 与 SDK Schema 兼容；无示例 ID/示例产品功能；模板路径与最终计划一致；安装时的唯一性和 hostApi 语义留 G1 验证，不靠本地 JSON 校验声称可安装。

**证据：** 模板来源摘要、身份与声明差异、文件预检结果。

## B2：接通宿主界面与异步偏好

**前置任务：B1。**

**目标：** 原工具箱在宿主 #app 内运行，保留分类/搜索/常用工具/主题等操作，正确处理存储失败和生命周期。

**修改范围：** `packages/ctool-core/src/tool.ts`、`helper/platform/runtime.ts`、`helper/pinia.ts`、`helper/storage.ts`、`helper/history.ts`、`store/setting.ts`、必要 `helper/cookieos/` 及入口/布局/路由配置。

**执行步骤：**
1. 移除运行时对 index→tool.html、popup 独立页面及浏览器/uTools/Tauri API 的依赖，保留业务页面；通过宿主桥打开支持的形态与外链。
2. 自动主题跟随宿主，手动主题/语言/缩放/常用列表仍有效；挂载前读取已知偏好，不将异步 xhub Promise 接入要求同步的 Pinia 插件。
3. CookieOS 平台保留内存状态，偏好按已知键显式异步保存，同键串行，失败保留“未保存”，不拿旧快照覆盖新选择。
4. 历史首先为会话内查看/清空；用户隔离未核定前不持久化输入。敏感内容不落普通存储/日志，不按上游版本自动删除旧偏好。
5. 默认不自动读剪贴板；复制被拒绝时明确反馈并可手动复制。卸载清理主题监听、timer、编辑器等资源。

**验收：** 分类/搜索/清空搜索、常用操作、主题变化、窄窗、键盘焦点及复制失败可用；慢加载、保存失败、连续保存、清空后迟到写入和多窗口同键保存有测试。不得承诺 SDK 未提供的 CAS/跨窗口事务或用户隔离。

**证据：** 原组件复用差异、浏览器行为断言、偏好调用计数及失败样例；D1/D2 复用此处模型选择键，不再建独立持久化路径。
